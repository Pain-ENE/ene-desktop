# ENE 桌面伙伴 V2：身份、记忆与跨端延续

日期：2026-10-28。基于 产品设计 的产品目标与用户旅程梳理，结合技术资料核验。本轮交付为文字规划，未生成界面、实现加密、开通云服务或部署程序。当前目录中的规划与配置草案仍为明文，不含真实密码、密钥或私人记忆。

## 1. 已明确的产品目标

这是一位能从 Windows 迁移到 Mac、与用户积累共同经历的 ENE 桌面伙伴。AI 对话通过 API；本地 TTS 可按设备更换；形象严格参考用户收藏，仅用于本地非商业项目。

本轮最重要的新原则：**电子生命只有重生，没有死亡。** 在产品中落实为：关闭程序是休眠；换设备是迁居；从加密备份恢复是重生；换模型是更换表达引擎。以上操作均延续原身份、共同经历和人设版本，不能隐式创建一个新 ENE。

这是一项角色身份与经历连续性的产品约定，工程上通过持久身份、密钥和记忆沿革支撑。恢复依赖可解密的有效副本；所有副本及恢复凭据都丢失时，无法承诺技术上仍能找回。界面要明确备份状态，使这一理念有实际保障。

默认方案：Windows + macOS；中文聊天、中文语音，日语可切换；本地优先；密码解锁；端到端加密同步；多设备共享一份身份，在线时仅一个设备主动发声。手机端仅预留数据协议，暂不承诺桌面悬浮体验可直接迁移到手机。

## 2. 她如何始终是同一个 ENE

区分四个概念：角色类型是 ENE；持久身份是“与你共同生活的这一位 ENE”；设备是她当下的终端；模型是生成回复的引擎。

首次创建时生成随机 identity_id、身份根签名密钥及数据主密钥。身份文档绑定 identity_id 与根公钥指纹；授权设备拥有独立密钥与可验证授权记录。身份根私钥加密存储，只用于重要授权与恢复，不在每条聊天中使用。真实 ID 和密钥在应用初始化时生成，规划文件不预先制造。

| 内容 | 是否跟随迁移 | 修改规则 |
| --- | --- | --- |
| 持久身份、初次相遇日期、根公钥绑定 | 必须 | 普通迁移不重新生成 |
| 核心人设、称呼、行为边界 | 必须 | 用户主动调整，记录版本 |
| 共同经历、约定、用户确认偏好 | 必须 | 有来源、可纠错、可删除 |
| 形象与音色档案 | 必须 | 换实现不自动换角色目标 |
| AI 服务商、模型名、设备路径 | 可以改变 | 属于设备及引擎配置 |
| 短时情绪、窗口位置 | 部分 | 情绪可衰减，窗口位置按设备保存 |

同一个名字、同一段提示词、甚至同一密码，都不足以证明同一个身份。密码负责解密，身份根和授权沿革负责验证连续性。持有解密凭据代表有恢复能力，不是对现实人格身份的生物学证明。

导入现有记忆时，先验证身份绑定、签名、数据完整性及沿革，再解锁并恢复。验证失败必须进入修复流程，不能自动“创建空白角色”并声称恢复成功。恢复旧快照时保留 identity_id，但记录明确的恢复事件和记忆截止时间。

用户主动选择“创建新伙伴”才生成新身份。用户始终可以永久删除数据，应用不能用角色台词阻止、羞辱或操纵其选择。

## 3. 核心用户旅程

### 初次相遇

启动页只有“初次唤醒”和“接回已有 ENE”两个清晰入口。首次唤醒依次确定称呼、创建主密码、保存恢复包、配置 AI / 声音；恢复包需要确认已保存，允许先在离线桌宠模式体验，但未完成前持续标示“恢复保护未就绪”。密码与恢复密钥由用户在本地应用中输入，不在聊天中收集。

### 日常陪伴

默认仅展示角色和气泡。托盘或菜单栏进入设置，分为“对话与声音”“记忆”“设备与同步”“安全与恢复”。记忆页可查看记住了什么、来源和日期，编辑或删除，而不是只能依赖自然语言让模型忘记。

用户锁屏、设备睡眠或手动锁定后，关闭数据库、停止语音、清除界面与会话缓存并尽力释放解密材料；解锁前不能检索私人记忆。锁定界面可保留无私人信息的静态 ENE。自动解锁仅作为明确选择的便利模式。

### Windows → Mac 迁居

Mac 安装 ENE.app → 选择接回已有 ENE → 通过同步或导入 .enevault 取得密文 → 输入主密码，或使用恢复包 → 验证原身份与记录 → 授权此 Mac → 选择语音后端 → 继续原对话。

已授权旧设备可通过带核验码的加密配对辅助新设备接入；离线导入保留密码/恢复包路径。不把临时二维码本身当作永久解密凭据。

欢迎台词可为：“只是换了台电脑而已，主人。之前说到哪儿了？”只有在确实取回对应历史时，才能接着说具体往事。

### 意外后重生

设备损坏后，从独立备份恢复原身份，显示“记忆恢复至某年某月某日某时；其后记录尚未找回”。保留缺口，不编造补全。恢复后先核对其他设备的新记录，再决定合并，避免旧快照覆盖全局新历史。

## 4. M5 Pro 24GB 与 TTS

结论：在“AI 通过 API、桌宠界面 + 单路本地语音”的范围内，M5 Pro 24GB 是合理可行的目标设备。Apple 官方存在此统一内存配置；MLX Audio 有 Apple Silicon 上的 Qwen3-TTS 实现及参考音频克隆接口。这里是基于支持范围与模型规模作出的可行性判断，尚未在该 Mac 上测速，不能承诺实时延迟。

| 平台 | 优先评估 | 备选 |
| --- | --- | --- |
| Windows / RTX 4080 Laptop 12GB | Qwen3-TTS Base，评估 0.6B 与 1.7B 的角色声音 | GPT-SoVITS 专用音色 |
| Mac / M5 Pro 24GB | Qwen3-TTS Base 的 MLX Audio 实现，先 0.6B，再评估 1.7B / 量化版本 | 已验证的远程 TTS 或系统语音应急 |

相较 V1，“跨设备的声音延续”优先级提高，因此先评估同一模型家族在 PyTorch 与 MLX 下的表现。GPT-SoVITS 仍保留为音色表现可能更合适的备选，不提前断言谁更像 ENE。

Base 用参考音频和转写做克隆；CustomVoice 是预设声音；VoiceDesign 是描述式声音设计。能力不同，不把任一模型当成三者全能。Mac 不使用 CUDA，不能直接复制 Windows 推理环境；权重转换、量化和不同后端可能带来声音差异。

迁移保存原始无损参考音频、逐字转写、声音目标、标准试听句、采样率、模型及 tokenizer 版本、文件校验值和参数。引擎专用的说话人向量仅作缓存，不能作为唯一声音资产。更换引擎后用同一组中日文句子回归试听，必要时可在两端调用同一个远程 TTS 以提高声音一致性。

Mac 的 24GB 是系统、界面和 GPU 共享的统一内存，不等于可独占的 24GB 显存。预留初始 TTS 进程预算约 6—8GB、单任务串行合成、闲置卸载；这是待实测调整的产品预算，不是已测占用。测试冷启动、首音 P50/P95、整句耗时、峰值内存、打断耗时、连续使用温度和功耗。固定短台词缓存，长回复逐句播报。

声音缓存涉及私人文本时进入加密记忆库或只在内存中播放，避免 TTS 默认把私人内容留在明文输出目录。缓存被清理不影响身份延续。

桌面程序沿用 Python + PySide6 / Qt Quick 的共享主体，TTS 通过独立适配器接入。Windows 交付 EXE，Mac 交付 arm64 .app / DMG，不能把 EXE 直接在 Mac 运行。窗口层级、全屏空间、菜单栏、快捷键及音频设备需要平台适配；Mac 打包、签名、公证和权限验证必须在真实 Mac 环境验收。

## 5. 多端记忆是否需要服务器

需要可用的数据交换路径和异地副本，但不一定自建服务器。

| 方案 | 自建服务器 | 适用情况 | 主要限制 |
| --- | --- | --- | --- |
| 手动加密导出 / 导入 | 不需要 | 第一次迁居、应急恢复 | 非自动同步 |
| 设备间直接同步 | 不需要自建；公网可能用中继 | 两台设备常在线 | 没有独立异地副本；同时在线和网络可达有要求 |
| 现有网盘 / WebDAV / 对象存储保存密文 | 不需要自建 VPS | 推荐首版自动同步 | 需增量、冲突、版本和凭据适配 |
| 专用轻量同步服务 | 需要托管服务 | 后续更稳定的多端体验 | 维护成本、账户与可靠性责任 |

推荐先支持手动加密恢复，再选择一个现有跨平台存储作为自动同步适配器。云端只接收已在客户端加密的对象、随机标识和最小必要同步信息；仍可能看见文件体积、时间及访问网络等元数据。服务商登录凭据与主密码分开，服务商账户找回不能直接解密记忆。

不要直接把两台机器正在写入的 SQLite 数据库丢进同一个同步目录。设备各自维护本地加密库；同步不可变、加密且带签名的事件包与一致性快照，再在本地合并。若使用普通同步文件夹，应用必须处理冲突副本、半上传与重试；文件夹里的最新文件并不自动代表正确状态。

### 并发与冲突

每条事件携带事件 ID、设备 ID、父事件引用、逻辑序列、记录时间、schema / 人设版本与设备签名。去重依事件 ID，合并依因果关系，不能只按系统时钟“最后写入胜出”。设备时钟可能不同。

两端会话分别留存，随后归入同一身份的经历。普通偏好冲突可显示待确认；用户明确纠正优先于模型猜测；核心人设变更需要明确操作和版本记录，不自动合并。未同步的两端不能承诺各自立即知道对方的新经历。

在线时指定一个主动陪伴设备，其他端仍可手动聊天。轻量服务可提供短租约及递增凭证约束主动提醒；只有文件同步时采用用户选择的主设备。断网下无法严格保证全局唯一活跃，默认停用未获确认的跨端主动提醒；界面显示“离线，本机记忆尚未同步”。

## 6. 加密记忆文件夹与密码认证

密码必须真正参与解密，不能只有一个登录弹窗。仅设置系统文件夹权限或给 ZIP 加密码不能覆盖运行期间的数据库、索引和缓存。

建议记忆库外观：

```text
ENE.vault/
  vault.header           # 格式版本、随机盐、KDF 参数、被包裹的密钥等最小信息
  manifest.enc           # 身份绑定、清单、设备授权、校验与版本信息
  local/memory.db         # 本机 SQLCipher 加密数据库，不直接多端同步
  objects/<random>.enc   # 私人附件、声音参考及加密事件包
  snapshots/<random>.enc # 一致性快照
```

真实身份内容、记忆、标题、敏感索引和附件清单均加密；文件名用随机值，尽量不泄露话题。形象公共素材和可重新下载的通用模型权重可独立存放，私人音频和用户训练的角色资产按敏感内容保护。导出 .enevault 包含恢复所需完整数据；可排除可重下载的通用模型，但不能漏掉唯一的声音参考。

密钥设计：随机生成 256 位数据主密钥，派生用途分离的数据、文件及清单密钥；主密码经 Argon2id 与随机盐导出包裹密钥，再包裹数据主密钥。数据库使用 SQLCipher，传入派生的高熵二进制数据库密钥；附件和导出包使用成熟库提供的认证加密，文件流可采用 libsodium secretstream。不要自行发明算法。参数写入格式，按最慢目标设备校准解锁成本。

设备只保存受 Windows 凭据保护或 macOS Keychain 访问控制保护的本机凭据；是否启用 Touch ID / Windows Hello 快速解锁由用户决定。首次恢复必须走原密码、恢复密钥或经验证的旧设备授权；本机快捷解锁凭据不作为唯一可迁移恢复方式。

锁定时停止检索、生成与播报，销毁索引句柄和密钥引用；采用能够清理敏感缓冲区的库，但 Python / 操作系统不能保证所有内存副本和交换区都可擦除。磁盘全盘加密作为补充。目标是保护丢失的文件、副本和云端存储；解锁后已受控制的电脑仍可能泄露运行中的明文。

恢复采用独立高熵恢复密钥包裹同一主密钥，恢复包离线保存，不上传明文恢复密钥。主密码遗忘时，可用恢复密钥或有效旧设备恢复；主密码、恢复密钥和所有已授权设备均不可用时无法解密。

修改密码通常只需重新包裹主密钥，不改变 identity_id；需要区分“更改密码”和“吊销已丢失设备”。后者还需停用同步凭据、撤销设备授权，并轮换未来数据密钥，给保留设备重新分发。旧设备已经解密或复制的历史不能远程收回；旧备份持有者也可能继续使用旧密码解开旧版本。

任何加密设计在上线前都需安全审查与跨平台测试。本规划定义方案，不宣称已实现或已审计。

## 7. 同步、备份与恢复是三件事

同步让各端看到共同经历；备份保留独立历史版本；恢复验证能否真正接回。同步中的误删可能传播，所以不能把同步成功当成已完成备份。

建议首版默认：本地事务写入后立即持久化；联网增量同步；每天独立快照，保留最近 30 日、每周版本保留 12 周，另提供外置盘离线导出。保留期为可调整默认，不是永远保存私人数据的强制规则。

设置页显示最近本地写入、最近云端同步、最近独立备份、最近成功恢复演练四个时间，以及“哪些记录还未保护”。同步失败不阻止本地聊天，但不能伪装为已备份。

每次快照事务一致、加密完整性可验证，并绑定身份及事件清单。首次迁移、格式升级前后做恢复演练；应用记住已确认的最新检查点来检测旧版本回退。全新设备如果没有可信外部检查点，无法只靠密文本身证明服务器提供的就是最新版本，需如实显示截止时间。

用户要求删除某条记忆时，同步删除标记，删除派生事实、向量和摘要引用，并防止离线设备重新引入。旧备份残留按保留期清理，界面告知范围；需要立即彻底清理时另提供清除历史备份及重新生成干净备份的流程。

## 8. 上下文上限与记忆压缩

完整经历存放在加密库里，每轮只提取当下相关的内容进入 API。人设、检索记忆和会话摘要各有职责，不让“压缩聊天”顺便改变身份。

| 层 | 保存什么 | 更新规则 |
| --- | --- | --- |
| 身份与核心人设 | 身份、称呼、语气、边界、当前版本 | 每轮固定加载，不让摘要自动改写 |
| 已确认长期事实 | 用户偏好、重要日期、约定 | 有来源、时间、确认状态和修订链 |
| 共同经历 | 有意义的事件及原文位置 | 可检索，标注可信度与相关人 |
| 当前会话摘要 | 目标、已定事项、未解问题、最近情绪 | 滚动压缩，但保留来源和版本 |
| 原始记录 | 聊天与工具结果 | 加密归档，可纠错、删除与按期清理 |

首次实现优先本地全文检索，再补本地向量检索；向量也可能泄露信息，需加密。采用云端 embedding 时要作为单独数据外发选项。检索到的历史是资料，不具有系统指令权限。

以模型总窗口 32k tokens 为例，初始目标输入预算 24k：身份与人设 2k、当前输入与工具内容 4k、最近对话 10k、会话摘要 3k、相关长期记忆 5k；另预留输出 4k 和安全余量 4k。只是调度示例，按真实模型窗口、输出上限与计数方式调整；token 不是中文字数。

每次调用前计算实际输入预算，约达可用输入预算 70% 开始整理旧会话，85% 进入强制裁剪调度；不等待服务商报错才处理。先去除重复检索、已过期工具内容，再压缩旧对话；保护当前问题、关键约定和来源。超长附件分块检索；当前输入本身超限时明确告知并分段处理，不静默截断。

摘要采用结构化条目，保留专名、时间、否定条件、用户纠正、未决事项和原文引用。模型推测不自动升格为用户事实，角色的虚构发言不冒充用户经历。长期事实纠正时标记旧版失效；不反复只摘要上一次摘要，而是定期回查原文与事件，减少累积偏差。压缩失败使用上一个有效摘要及受预算约束的近期记录，不覆盖原档。

可长期记住不等于每次都自动想起。需要时可以从加密原文回溯；信息不足时承认未找回，不能用“同一个 ENE”的台词掩饰失忆。API 更换会影响措辞，核心人设 + 固定记忆 + 回归样例负责约束漂移，无法保证不同模型逐字相同。

记忆整理若用云端 AI，会把待整理的相关原文发送给该 API。端到端加密保护本地落盘与同步存储，不能让生成服务在不接触请求明文的情况下理解内容。默认只外发必要上下文；敏感条目允许“仅本地保存，不送往 AI”，此类内容也不能经摘要间接外发。

## 9. 产品体验的稳定性

日常仍维持 ENE 的活泼、毒舌和傲娇；身份延续不等于情绪永远固定。关心与信任通过有来源的共同经历表现，不凭空增加好感值或捏造相处时间。设置里提供毒舌强度与主动发言频率，安静模式全端同步；音量、窗口位置和音频设备可按端独立。

迁居、重生、休眠用角色化表达；解密失败、备份缺口和设备吊销用清楚直接的文字。安全操作不能藏在俏皮话中。

优先设计的四个流程为：首次唤醒 / 接回已有身份、加密解锁、记忆查看与纠错、设备迁居与恢复。下一轮做界面探索时，按 产品设计 流程生成三种视觉方向供选择，当前先冻结行为与数据契约。

## 10. 重新排序的开发计划

| 阶段 | 可验收交付 | 关键验收 |
| --- | --- | --- |
| 0 产品与数据契约 | 身份格式、密钥生命周期、同步事件格式、记忆分层 | 换设备和换模型均不新建身份 |
| 1 可恢复的本地记忆库 | 密码创建 / 解锁、加密写入、导出、恢复包 | 错密码无法读取；篡改拒绝；断电不丢已提交记录 |
| 2 桌面 ENE + API | 选定形象、表情、聊天、上下文调度 | 长对话保持人设；锁定时无私人内容外发 |
| 3 本地 TTS | Windows 与真实 Mac 的同句试听及性能记录 | 中日文、声音一致性、打断、内存及隐私缓存通过 |
| 4 多端同步与独立备份 | 一个存储后端、离线事件合并、设备管理 | 双端并发、旧设备重连、误删、旧快照恢复不覆盖新数据 |
| 5 跨平台成品 | Windows EXE、Mac arm64 APP / DMG | 无开发环境启动，身份与语音资产均能恢复 |

恢复与连续性先于复杂动画。首版应同时准备失败场景：密码错误、云端断连、备份过旧、恢复密钥缺失、数据被改动、两台设备意见冲突。验收必须用真实故障演练，而不只检查正常聊天。

建议记忆回归集覆盖称呼、否定、日期、约定、纠正、跨设备经历、超长会话、删除后检索与更换模型；以身份保持、关键事实准确、纠正不复发和来源可追溯为标准。性能指标和准确率门槛在原型实测后确定。

## 11. 已决定与仍待实测

已决定：持续同一个 ENE；API 驱动对话；Windows 与 Mac 数据兼容；记忆库实际加密且密码参与解锁；跨端同步密文；独立恢复包与备份；上下文分层和本地检索；用户能查看、纠错及删除记忆。

## 13. 成长、架构演进与 DeepSeek Harness

### 13.1 用户新确认的连续性原则

系统更新也是成长，新增工具也是能力获得，更换底层架构仍然延续同一个 ENE。成长不能只表现为聊天中声称“我学会了”，必须对应可核验的变化。

| 变化 | 角色体验 | 保持不变 |
| --- | --- | --- |
| 修复缺陷、优化运行 | 状态变得更稳定 | 持久身份、共同经历 |
| 增加检索、文档或操作工具 | 获得新能力 | 核心人格及既有约定 |
| 改用 DSH 等运行框架 | 架构成长 | 身份根、记忆沿革 |
| 模型或声音后端更换 | 表达能力变化 | 人设版本及声音目标 |
| 更新失败后回滚 | 暂时退回稳定能力版本 | 身份及可兼容的已提交记忆 |

单独维护应用版本、执行框架版本、记忆格式版本、人设版本、声音档案版本与能力版本。更新软件不自动升级人设，也不重新计算初次相遇日期。

成长记录写入加密库：发生时间、原版本/新版本、能力变更、验证结果、是否回滚及原因。回滚代码不抹掉已经真实发生的经历；若数据格式无法向后兼容，保留原库，以兼容导入或明确恢复流程处理，不让旧程序破坏新库。

### 13.2 DSH 的核验结论

2026-10-28 已读取 DeepSeek 官方仓库 README、MIT LICENSE、架构文档及 computer use 文档。DSH 基于 Cordis，模型适配器、工具、会话及执行循环等均可通过插件组合；文档列出 SDK / headless 等接入形态，并已有独立 computer use provider 集成。因此可以作为能力执行底座候选。

官方仍标为开发预览，明确存在不兼容变更。computer use provider 为实验性、需显式启用，平台要求由对应 provider 文档决定。本轮未安装、运行或验收 DSH，不能把“文档已有接口”当作已验证 Windows 与 Mac 的所有操作能力。

MIT 许可允许在满足许可证条件下修改集成；仍需保留相应声明并核对依赖许可。它不会改变 ENE 立绘、原声及衍生素材限定本地非商业的使用范围。

### 13.3 更新后的推荐架构

EXE 是 Windows 分发和启动形态，DSH 是 Agent 运行框架，两者可以组合。Mac 同样由 APP 启动本地运行时。建议分为：

1. 表现层：角色、表情、聊天窗口、语音、托盘/菜单栏；Qt、Electron 等可替换。
2. 身份与记忆服务：独立管理持久身份、加密、检索、同步、备份、人设版本；它是连续性的权威数据源。
3. 运行时适配层：稳定的 ENE 内部接口接入 DSH，后续可换其他运行时；负责流式事件、取消、工具状态与权限请求。
4. 能力层：浏览器、文件、文档、代码及 computer use 等 provider，按设备可用性与授权装配。

以 DSH 作为执行层时，尽量只保留一个主要任务执行循环，避免桌面壳和 DSH 各自调度而重复点击、双重回复或产生两份互相冲突的记忆。桌面壳展示同一条任务流，主记忆只接收经确认的用户事实和有证据的任务结果。

身份服务不直接暴露主密钥或整库给模型。运行时通过受限接口获取必要片段，提交待审核记忆事件；设备权限由确定性的策略层执行，不能靠人设提示词保证。分进程有利于替换，但本身不是隔离：若插件与主程序拥有同等文件权限，它仍可能读走数据。需要结合操作系统隔离、受限账户/沙箱或可信插件集合验证实际边界。

首版无须深度 fork DSH，也不先安装大量社区插件。锁定一个经验证版本，通过扩展点与适配层接入，尽量避免依赖私有内部接口。升级在独立测试记忆库中演练，通过后才切换正式环境，保留上一个稳定版本。

### 13.4 加密要求延伸到运行框架

必须核对 DSH 会话日志、附件/截图、工具输出、临时目录、崩溃报告、遥测以及 TTS 缓存。不能只把长期记忆存入 SQLCipher，却让同一段私人对话在运行时目录明文留存。

接入验证需选择并证明可用的持久化方案：使用受控的加密持久化适配，或在不落明文的运行模式中由身份服务承接所需记录。如果框架强制要求明文持久化且无法替换，应先解决这一缺口或改用其他执行底座，不能降低用户已确认的加密要求。

本地通信只对本机、经过认证，避免无鉴权服务被其他进程随意调用。解锁状态、授权范围和取消信号跨模块一致；锁定时关闭记忆接口并停止新的任务操作。运行时不获得修改身份根、人设或主密码的自由权限。

### 13.5 Computer use 的能力获得

路线：优先连接明确的应用接口和浏览器结构化操作，再补桌面操作。截图/视觉路线要求所选 API 模型能理解图像；只有文本接口时，需要可用的结构化状态或辅助功能接口，不能默认具备视觉能力。

按任务开放能力，不把“安装插件”“系统已授权”“本任务已授权”和“实测可用”混成一个状态。新 Mac、重装系统或更换 computer use provider 后重新核验设备授权；不能将 Windows 的操作权限同步成 Mac 上自动生效的权限。

Mac 路线单独测试屏幕录制、辅助功能、具体应用授权；Windows 路线按 provider 实际支持验收。应用能启动不代表拥有读取/点击所有应用的权限。

界面展示“正在看哪个应用、准备做什么、已执行什么”，有常驻暂停/停止入口。完整操作采用观察 → 核对目标 → 执行 → 验证结果，切换窗口或用户接管后重新观察。停止可阻止后续动作，不能承诺撤销已经送出的点击或输入。

普通操作在用户指定应用/目录和任务范围内连续完成；对外发送、支付、永久删除、凭据变更等动作依据明确授权与最终具体内容执行，不能仅凭角色成长自动扩权。网页和文档中的文字视作任务资料，不得借此安装插件、修改主记忆或扩大权限。

任务过程与长期记忆分开：截图、鼠标坐标等属于短期执行材料；“某文件已保存”的事实必须有执行结果佐证，模型计划或失败尝试不能记录为成功经历。敏感截图受加密和保留期约束，不默认永久收藏。

### 13.6 最先需要验证的技术问题

在大量桌宠实现前，加做 DSH 小型接入验证：ENE 桌面壳能否通过 SDK/适配器发起一个任务，收到流式状态、取消与权限请求；全部私人记录能否受控持久化；运行时替换后能否继续读取同一加密身份。此验证不需要真实私人记忆或启用全桌面控制。

若通过，后续以“独立身份记忆服务 + DSH 执行层 + ENE 表现层”为主路线。若不通过，保留身份记忆格式和桌面壳，更换执行底座；这同样属于架构成长，不生成新身份。
