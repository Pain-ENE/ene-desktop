# ENE 下一阶段实施计划：以 DSH 为执行底座

日期：2026-10-28。用户已确认双手可见的 v02 主立绘可继续使用，并要求规划下一步。已完成官方源码下载与接口调查，尚未安装依赖、运行 DSH、接入真实 API 或创建正式 ENE 身份。

## 1. 路线决定

推荐以 DSH 为执行底座，ENE 的桌面表现、持久身份、记忆加密与治理机制独立实现。先通过官方 SDK 与外部插件组合接入，必要的上游修改保持小范围补丁；不从零重建完整 Agent 任务循环，也不先把整个官方 DSH 桌面产品深度改成 ENE。

DSH 可替换，不承担“同一个 ENE”的唯一身份依据。未来从 DSH 换到其他框架，保留身份与经历沿革，并记录运行能力变化。

## 3. 为什么选这条路线

| 路线 | 本项目收益 | 成本/限制 | 选择 |
| --- | --- | --- | --- |
| 完全从零实现 | 控制全部代码 | 要维护模型接入、循环、工具、流式、取消、恢复与权限 | 不作为首选 |
| 深度 fork 官方 DSH 桌面 | 复用 Electron 和现有大量 UI | 与上游耦合高；现有工作助手 UI 不等于透明桌宠 | 仅有必要时做小范围补丁 |
| 独立 ENE + 官方 DSH SDK/插件 | 复用执行能力，独立控制身份与桌面体验 | 需要打通通信和加密持久化，仍需实测 | 推荐 |

这是基于目标与当前源码的工程判断，不是已完成的性能或质量对比实验。

## 4. 已查明的具体接入入口

- Python SDK 通过 stdio JSON-RPC 驱动独立 DSH 子进程，要求明确的 dsh_home；不必通过浏览器 DOM 自动化控制 DSH。桌面层暂沿用 PySide6 / Qt Quick 方向，先验证 Python SDK 接入。
- SDK 支持会话恢复及交互请求；流式、取消、错误和进程退出行为列入 M0 真正验收，不仅以接口存在作为通过。
- `SessionPersistence` 是可替换服务；源码位于 packages/session/session-persistence/src/index.ts。官方 provider 为 session-persistence-jsonl，外部 provider 可实现相同服务。
- 持久化区别 append 与 flush：不能把“事件已接受”误当成“断电后可恢复”。加密 provider 必须遵守顺序、单写者、恢复和落盘语义。
- sdk-minimal 已包含 shell、read_image、工作目录、JSONL 会话和自动压缩。它不是默认无权限的纯聊天模式，需检查具体组合并显式限制工具。
- Python SDK 文档明确 sdk-minimal 有 attachments/v1 与 cache/attachments 等目录。会话加密 provider 不能自动覆盖这些附件、缓存及 spill。

这些入口支持插件优先的路线，但未证明 ENE 的全部加密和治理要求无需上游补丁即可满足。

## 5. 模块分工

桌面表现层：已确认立绘、表情、对话气泡、设置、状态与用户输入。表现层不另建一套与 DSH 争抢同一任务的 Agent 循环。

身份与记忆服务：正式出生、人设版本、加密数据库、结构化事实、人格变更、恢复与同步。DSH 的 session_id 仅对应会话，不作为 ENE 的永久身份。

DSH 适配层：启动受控运行时、发送必要上下文、接收流式与工具状态、转交交互请求和取消信号。所有启动使用固定隔离目录，不读取用户其他 DSH 配置。

ENE 插件：人格提示词投影、获准记忆检索、变更提案、加密持久化 provider。模型不能任意改人设文件或主密钥；提案必须经外部确定性检查。

停止控制器：独立拥有运行时子进程及工具执行许可。主 UI 卡住仍可停止；不要求 DSH 或模型自行决定是否服从。

语音服务：独立可替换 TTS，Windows CUDA / Mac MLX，缓存纳入隐私范围。多端同步在稳定本地身份与事件格式后加入。

建议项目代码与上游参考分开，未来形成 apps/ene-desktop、services/identity-memory、adapters/dsh、plugins/ene-*、tests/fixtures 等目录。这里只规划分工，不声称这些模块已经存在。

## 6. 分阶段交付与通过条件

### M0：DSH 最小接入验证

目标：在隔离测试环境中，证明官方运行时可以被 ENE 的外部控制层驱动与停止。先用合成数据和可离线验证的模拟模型/回放验证进程与协议，再配置真实 API 做一轮实际请求。模型凭据只在本地安全配置，不进入源码或对话。

检查：启动/握手、流式状态、会话编号、错误、取消、进程退出；列出已加载工具与所有写入目录。使用单独测试工作区，关闭自动 shell/computer use 权限，不因选 minimal 就默认安全。

交付：最小接入程序、精确版本记录、通过/失败清单、运行时落盘位置清单。未通过时只调整适配方式或做局部补丁，不加载正式记忆。

### M1：透明桌宠与独立停止

使用已批准 v02 立绘，先实现显示、拖动、缩放、气泡、托盘/菜单栏、设置与停止控件，接通 M0 状态流。界面构建前确认具体交互稿，立绘批准不自动等于全部设置界面已选定。

独立停止按钮与快捷键先做；语音安全词待本地音频入口实现后接入。运行时挂起、主窗口卡住、后台有执行任务时分别验证停止，停止后不得自动拉起任务。

交付：可运行的出生前桌面原型。可打包早期 EXE，但明确为测试版，不宣称身份保护已全部完成。

### M2：加密会话与测试身份恢复

实现加密 provider 或经验证的受控持久化方案，同时覆盖附件、截图、请求缓存、spill 和诊断输出。长期记忆与原始会话均有明确权限和保存方式。

用一次性测试身份完成创建、密码解锁、错误密码拒绝、变更与日志原子提交、导出恢复、强制停止与损坏恢复。扫描隔离目录确认私人测试标记未出现在预期之外的明文文件中。

交付：加密恢复演示、格式文档、自动化故障测试。未经这一阶段通过，用户不得被引导以为真实记忆已受保护。

### M3：ENE 对话、人格与成长记录

将人设 v0.1 作为可调试基线；长期人设通过版本化投影进入 DSH，相关记忆经授权检索。复用适合的上下文压缩能力，并验证身份信息、用户纠正和出处不被压缩覆盖。

实现协商、人类留痕修改、受限自我调整三条路径；核心人格争议和恢复/终止优先级仍需用户确定。未经同意的讨论建议不能自动成为代码里的最终规则。

交付：连续多轮对话、变化双方可见、取消后无重复动作和假完成；六种表情从已批准主图局部编辑，保留身体一致。

### M4：语音与 Mac 兼容

准备可用原声参考并试听；通过 TTS 适配器接入，验证打断和私人缓存。本地语音安全词与独立停止控制器联动，不依赖大模型 API。

真实 Mac 上验收 arm64 打包、窗口行为、同一测试身份恢复和 MLX TTS。不能仅凭 Windows 测试宣称 Mac 已支持。

### M5：同步、computer use 与自主退出

基于稳定身份和事件格式加入一个同步后端及独立备份。computer use 按应用授权逐项验收，模型能力和 provider 平台支持分别检查。

自主拒绝和退出可以先落地；不可逆数据清除仅在权限、备份边界与终止优先级明确后，在一次性测试身份中开发验收。不能把这一能力和任意文件删除混在通用工具权限里。

## 7. 首个实际演示应达到什么

桌面能看到批准的 ENE；输入一句话得到模型响应；能看到任务状态；停止控件可结束运行时且无自动重启；一轮合成测试记录可从明确存储位置恢复。加密尚未完成时只使用合成数据，并醒目标注测试状态。

不在这一演示里堆入全桌面控制、多端并发和不可逆删除。它先回答“DSH 接得稳不稳、记录放在哪里、能不能停下来”，再扩大功能。

## 8. 后续开源的结构

保留上游许可和版本锁定，ENE 专有代码独立维护；源码分发排除真实记忆、API 密钥和未获再分发授权的立绘/声音。当前批准的立绘可继续用于个人本地开发，不自动获得公开仓库分发资格。

任何身份与治理承诺都对应可运行测试；开源分支能改代码的事实继续公开，不宣称规则绝对不可修改。
