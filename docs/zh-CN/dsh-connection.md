# ENE 与 DSH 当前连接说明

本文件描述已实现代码，不把规划当成已完成能力。

## 为什么 ENE 界面不像 DSH

当前采用独立桌面界面加官方 DSH SDK/运行时的路线。ENE 管窗口、立绘、气泡、输入和姿态；DSH 在后台负责执行会话。没有复刻或深度修改官方 DSH 桌面客户端，因此外观不相似。

## 实际调用链

ENE React 界面 → 受限 IPC → Electron 主进程的 RuntimeController → 独立 Node 24.21.0 worker → 官方 DeepSeekHarness SDK → DSH 0.2.2-alpha.2 的 sdk-minimal 进程 → llm-pi-ai 兼容路由 → 本机 HTTP 合成测试服务。

DSH 在发送演示消息时按需启动，不要求一打开 ENE 就同时打开官方客户端。设置中已显示后台引擎版本和是否有 worker 运行。

## 当前还不是正式 AI 对话

`native/runtime-worker.mjs` 只向 DSH 发送固定合成标记，不转发用户输入。通过真实 DSH 收到 `ENE_SYNTHETIC_OK` 后显示固定演示回复。这验证的是依赖、进程、协议、错误与停止链路，不验证模型智能。

聊天输入和历史目前仅保存在当前聊天渲染进程内存。尚未接通真实服务商、正式人格上下文、长期记忆检索、加密持久化、TTS 或 computer use。DSH 测试会话仍只有合成标记且为明文，不是 ENE 正式身份。

后续接真实兼容 API 时，需要供应商地址、模型名、实际上下文容量与本机安全凭据配置；再把真实对话、人设与获准记忆投影交给 DSH。不能仅改“已连接”标签便宣称这些已完成。

## 姿态的关系

当前站立、坐姿、趴姿是三个静态素材，由用户在右键姿态菜单或设置中切换。窗口停靠使用坐姿。尚无眨眼、走路或由模型控制姿态的动作系统；后者应通过受限动作指令实现，不能让模型任意改窗口或运行系统命令。

关键代码位于 `apps/ene-desktop/native/main.mjs`、`native/controller.mjs`、`native/runtime-worker.mjs`、`adapters/dsh/runtime.mjs`。供应商未确定，不要求用户把密钥发送到聊天中。
