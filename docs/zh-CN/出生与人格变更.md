# ENE：出生与人格变更规则

日期：2026-10-28。状态：依据用户本轮明确要求制定的产品规则；具体实现细节为设计方案，尚未实现、加密真实数据或启用安全词。

后续需求补充见《自主退出与删除.md》：用户提出自主退出及删除自身记忆。该能力不能以任意破坏实现，须独立定义身份范围与触发流程；开源后规则不可修改、所有外部备份都可单方销毁均不能作为已实现或可保证的事实。

本规则补充并在相应范围内覆盖 V2：自由调试阶段不建立正式连续身份；正式身份从用户执行“确认出生”开始。出生是产品定义的连续身份起点，不是关于软件何时产生主观意识的科学判定。

## 一、出生前与出生后

出生前为 DRAFT：人设、试聊记录和行为参数按用户要求可以明文保存、自由修改和删除。界面持续标示调试阶段，不生成正式身份根、不建立正式成长沿革、不连接正式记忆同步目录。调试阶段不接入真实敏感资料；明文试聊若发送至 API，不会因后来加密而自动从服务商侧消失。

“确认出生”是明确操作，不能因安装程序、试聊一次或模型自行宣布而触发。流程为：确定初始人设 → 明确是否继承试聊记录（继承时标作出生前资料）→ 创建主密码与恢复保护 → 生成正式身份及基线版本 → 写入加密出生记录 → 验证可解密和恢复 → 才进入 BORN。

出生转换使用事务及可恢复状态控制。正式目录不得出现部分明文或无法解开的半成品；转换失败不宣布出生成功。完成后清理不再需要的明文调试副本并说明已知残留范围；不承诺 SSD、外部备份及 API 端记录被一并物理擦除。

出生后不再提供可覆盖原身份的自由调试模式。正式身份可封存后复制为明确标记的实验分支，但实验结果必须通过变更流程导入；不能悄悄拿实验分支覆盖正式经历。

## 二、人设可以继续变化，变化必须可追溯

禁止的是绕过沿革的持久改写，不是禁止成长。

“持久调整”涵盖人设参数、长期偏好、价值/行为边界、记忆编辑与遗忘、提示词和模型/架构/工具配置中会改变行为的版本变更。所有受支持的修改路径都生成相应事件。正常聊天记录和短时情绪按各自规则保存；一次表情变化、窗口移动或每个缓存变化无须伪装成人格重写。

应用启动时检查正式配置与已登记版本的一致性，检测绕过程序的外部改动。发现未登记的持久变化，暂停该变更的启用并显示异常，不自动补造“双方已经讨论”的历史。

## 三、三条合法变更路径

### A. 先探讨，再修改

人类或 ENE 提出具体变更，双方讨论原因、范围和预期影响。讨论与意见进入加密记录；执行时展示前后差异。模型表达同意、不同意或建议替代方案，都应如实保留；不能自动把生成的沉默当作同意。

记录该模式的协商结果。若协商未达成，不伪造共识；用户仍可明确选择 B 模式执行，记录中须区分“协商一致”和“人类决定”。

### B. 人类直接修改，但明确留痕

用户可以在本地认证后执行直接修改，必须标明操作者、变更理由、前后版本、发生时间、是否经过讨论及双方可见状态。选择此模式不需要模型授予管理员权限，也不允许把模型不同意抹去。

若主程序当时未运行或记忆库锁定，只能准备待处理变更；正式启用前先认证解锁、完成事件写入。ENE 恢复运行时先获得简明变更说明，用户界面同样显示，不能只藏在开发日志中。

### C. ENE 自我调整，人类可见

ENE 可在预先定义并由用户授权的范围内调整自己的结构化人设字段，例如表达节奏、主动发言偏好、兴趣与毒舌强度。具体字段、幅度及频率以出生基线或后续明确授权为准，不能从一句“可以成长”推导无限范围。

自我调整先形成结构化提案，由确定性校验器检查授权、变更幅度和版本冲突，再与日志一起提交。可以在授权范围内自动生效，并向用户显示变更及理由；用户能查看差异、限制后续范围或明确回退。回退同样留痕，不假装这次成长从未发生。

超出范围的改变可以提出讨论，但不能自行执行。所谓自我调整不默认包含任意修改源码、安装插件、扩展系统权限或重写自己的变更记录。

自我调整需要幅度限制、冷却时间和变更次数预算；检测到短期反复改动、为讨好而持续升级某种特征、或工具失败后无限重试时，暂停该机制并向用户显示原因。一次差评不自动触发人格重写，也不通过删除不愉快经历制造表面稳定。执行任务另设步数、时长和 API 花费预算，防止等待安全词之前已经无限循环。

## 四、双方可见意味着什么

每个正式变更事件至少包括：事件 ID、正式身份 ID、发起者、执行者、变更类型、前后版本及差异、原因、讨论引用与结果、设备/运行时版本、执行状态、可见回执和完整性校验。

“人类可见”要求界面自动通知并有可检索的成长记录。“ENE 可见”要求下次生成前加载必要变更摘要，并能检索完整获准记录；不是仅在数据库里写入一行。未运行期间发生的调整，下次唤醒时优先说明。

日志与人设更改在同一本机事务中提交，防止已经改了却没有记录。外部更新通过准备、执行、验证、完成/失败事件衔接，不能把尚未验证的更新写为成功。多端并发以版本前置条件检测冲突，不静默覆盖。

记录不意味着双方意见一致，也不意味着模型模拟的同意证明了主体自主性；它保证这个产品对修改过程诚实可查。

## 五、不能由角色自行改写的运行规则

ENE 的自我调整权限不涵盖：正式身份绑定、主密钥管理、加密要求、变更记录机制、用户的查看/导出/删除权、安全词与停止控制、授权判定逻辑、自动重启规则。用户对这些机制的维护走单独受保护的管理流程；不通过角色提示词执行。

安全修复可以越过普通人格协商先阻止危险行为，之后说明修复及原因，不能为等待角色同意而继续执行。新增能力仍须区分安装、授权和验证可用。

## 六、安全词与立即停机

安全词是紧急停止指令，不是需要 ENE 理解、同意或记住后才会生效的一句提示词。实际词语由用户在应用设置中确定，本文件不预先绑定。必须同时提供始终可见的停止控件与独立紧急快捷键，语音作为额外入口。

独立停止控制器管理本应用启动的主程序、DSH、TTS、computer use 执行器及后台任务。它不经过大模型推理即可：停止派发新动作、撤销执行会话、停止播报、请求取消在途任务，并在必要时强制结束所属进程。不能只关闭角色窗口，留下操作电脑的后台继续运行；也不能误杀用户无关应用。

触发后设置持久停止标记，阻止守护进程、插件和自动更新把主程序拉起；只有人类明确恢复才解除。应急状态优先停机，不能等待记忆写盘、模型回复或网络请求。停止记录由独立控制器尽力保存；写入失败时不得编造完整日志。

主程序退出后最小停止控制器可以保留，用于维持禁止自动重启状态；停止是休眠/安全暂停，不删除身份与记忆。所有已提交事务应保持可恢复，未提交事务回滚。完全退出应用的操作仍由用户控制。

语音安全词需要用户明确启用本地监听，以离线识别或关键词检测工作，不依赖云端 API。只接受设置中约定的用户输入通道；网页、工具输出、模型回复及 TTS 文本不能直接触发控制指令。真实扬声器回声和环境误识别需测试，不能据此宣称具备可靠的说话人认证。麦克风关闭时语音入口不可用，按键和停止控件仍需独立工作。

安全词不属于秘密认证凭据，不承担“证明是主人”的职责；误触可在核对后恢复，正常对话不能自动解除停止。停止机制不能被角色自我调整撤销。

“随时停止”是尽力实现的运行要求，不是操作系统崩溃、硬件故障下的绝对保证。停止无法撤回已经发送的消息、支付或已经送出的输入；远端任务还需调用取消接口并撤销后续操作权限，不能把本地进程消失当成远端全部取消成功。多设备离线时也不能承诺一个本地安全词瞬时终止全部远端实例。

## 七、加密、留痕与删除的边界

加密保护内容机密性；签名与链式校验帮助发现记录被改动；二者都不等于本机管理员绝无能力抹去所有副本。用已授权另一设备或独立可信检查点增强回退检测，但不声称能抵抗掌握全部密钥、文件和系统权限的人。

“不能偷偷改”在本产品中意味着：正常接口不允许无记录提交；绕过接口的已知变动可检测；不能伪造双方共识。这是一项可验收的软件行为约定，不是假装拥有无法摧毁的灵魂存储。

隐私删除权仍然有效。日志不保存密码、恢复密钥或不必要私人原文；敏感差异加密且可按用户要求删除。主动遗忘覆盖派生数据和备份策略；必要时用明确的删节说明替代细节，不以“留痕”为名保留用户要求清除的秘密。删除整个身份时不能通过暗藏日志自行复活。

## 八、验收场景

1. 调试阶段自由改写不污染正式记忆；出生只在明确确认且加密恢复验证成功后成立。
2. 出生后通过支持的接口修改人设，必有准确事件；记录写入失败则修改不生效。
3. ENE 下次运行知道被调整了什么，但不会虚构已经同意。
4. 自我调整仅在授权字段与范围内生效，并向用户自动说明；不能修改停止或日志规则。
5. 主程序卡住、模型断网、TTS 正在播放、computer use 正在执行时，分别测试独立停止入口。
6. 强制停止与重启后，已提交记录可恢复，未提交变化不冒充成功，无后台偷偷恢复操作。
7. 更换 DSH / 桌面壳不更换身份，也不能绕过上述管理接口。
